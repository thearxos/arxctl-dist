Pillaging

Post-foothold data gathering on a compromised Windows host - enumerating installed applications, looting remote-management configs (mRemoteNG confCons.xml and its hardcoded master password), stealing IM-client session cookies from Firefox and Chromium to ride a user's Slack/Teams session past MFA, logging the clipboard for pasted secrets, and abusing a backup system (restic) to snapshot and restore the SAM/SYSTEM hives for offline hash extraction and pass-the-hash.

MITRE T1005, T1539, T1552.001, T1003.002D3FEND D3-FA, D3-CHIMPACT CredentialTheft, PrivEsc

TL;DR

Pillaging is the post-foothold hunt for anything that extends access - credentials, session tokens, infrastructure detail, sensitive data. Distinct from the targeted credential hunting sweeps, this is about applications and their stored state: management tools, browsers, IM clients, the clipboard, and backup systems.

Success indicator: recovered credentials, a usable session cookie that logs you into the user's cloud IM, or - via a backup system - the SAM/SYSTEM hives yielding local hashes for reuse.

Management-tool configs - mRemoteNG

mRemoteNG saves connection credentials to confCons.xml in %APPDATA%\mRemoteNG. If the user didn't set a custom master password, it encrypts with a hardcoded default (mR3m) - so the stored passwords are trivially recoverable:

Copy the Password value and decrypt with mRemoteNG-Decrypt:

If a custom master password is set, decryption fails with MAC check failed; crack it by looping a wordlist through the script against the Password (or the file's Protected attribute) until one returns the plaintext. The same pattern applies to other management tools that store "encrypted" connection secrets with recoverable keys.

IM-client session cookies (Slack / Teams)

If a user is signed into Slack or Teams and you can't get (or MFA blocks) their password, steal their session cookie and replay it to log in as them in a browser. Slack's auth token lives in the cookie named d.

Chromium encrypts the cookie value with DPAPI, so decrypt it in the user's session with SharpChromium / Invoke-SharpChromium:

Load the recovered d value into a browser with the Cookie-Editor extension, point it at slack.com, refresh, and you're in the user's workspace - search chats for passwords/PII. Replay the same cookie on any sub-prompt.

Caution

The Chromium DPAPI path works on legacy/older profiles, but Chrome 127+ App-Bound Encryption blocks same-user DPAPI decryption of the cookie store - as covered on stored credentials, a current Chrome profile needs ABE-aware tooling or in-browser extraction instead. Firefox (no ABE) remains straightforward.

Clipboard

Backup systems

Backup servers and agents are crown jewels: the backup account usually has local admin on every protected host, and the backups themselves contain those hosts' sensitive files - including registry hives. If you land on one, loot the backups.

Using restic as the example (many enterprise systems follow the same shape), you can snapshot protected data - --use-fs-snapshot takes a VSS copy so even locked files like the registry hives are captured - then restore it and extract hashes offline:

From the restored SAM/SYSTEM (under C:\RESTORE\...\Windows\System32\config), extract local hashes with impacket and reuse them - this is the same hive-to-hashes flow as Backup Operators:

The recovered NT hash is pass-the-hash-able (unlike the NetNTLMv2 from forced-auth capture), and a local-admin hash often works across hosts that share it.

Defense

  • Set a strong, non-default master password on mRemoteNG and similar tools - the hardcoded mR3m makes "protected" configs plaintext. Better, don't store privileged creds in connection managers at all.
  • Protect browser cookie stores (Chrome App-Bound Encryption), and treat session-cookie theft as credential theft: short session lifetimes and re-auth on sensitive actions blunt cookie replay even with MFA.
  • Harden backup infrastructure as tier-0: dedicated, least-privilege backup accounts (not domain/local admin everywhere), encrypted repositories with protected passwords, and tight ACLs on repos and snapshots.
  • Monitor for clipboard-logger and cookie-extraction tooling, bulk reads of browser profile/AppData paths, and unexpected restic/backup-tool invocations.
