Miscellaneous Techniques

A grab-bag of Windows escalation paths that don't fit the token/group/service buckets - living-off-the-land binaries (certutil, rundll32), AlwaysInstallElevated MSI abuse, the CVE-2019-1388 UAC certificate-dialog GUI breakout, weak-ACL scheduled-task scripts, credentials stashed in account description fields, and mounting captured VHDX/VMDK virtual disks to pull the offline SAM. Each is a quick enumeration check worth running before heavier work.

MITRE T1068, T1140, T1003.002D3FEND D3-PSA, D3-FAIMPACT PrivEsc, SystemCompromise

TL;DR

A set of independent checks that each take seconds and occasionally hand you SYSTEM for free. None is a methodology - they're pattern-matches to run alongside the main loop.

Success indicator varies by technique: a SYSTEM shell (AlwaysInstallElevated MSI, CVE-2019-1388, a hijacked SYSTEM task), a recovered password (description field), or offline-crackable local hashes (mounted virtual disk).

Living off the land (LOLBAS)

The LOLBAS project catalogues Microsoft-signed binaries with unexpected, attacker-useful functionality - file transfer, code execution, DLL loading, UAC bypass. Because they're signed and native, they slip past application whitelisting and look less suspicious than dropped tooling, which matters most on a locked-down managed workstation or an evasive engagement.

certutil.exe (intended for certificates) is the classic - it downloads files and base64-encodes/decodes them:

rundll32.exe executes a DLL export, so a payload DLL (local or on an SMB share) becomes a reverse shell. LOLBAS isn't itself an escalation - it's the plumbing (get your tool across, run it, evade) that the other techniques rely on.

Caution

certutil download and the common LOLBAS one-liners are now heavily signatured by AV/EDR - certutil pulling an executable from an HTTP URL is a well-known IOC. Use them where whitelisting is the obstacle (signed binary needed) rather than assuming they're quiet, and prefer a less-watched LOLBAS entry when evasion matters.

AlwaysInstallElevated

A Group Policy misconfiguration that lets any user install an MSI as SYSTEM. The elevated install requires both the per-user (HKCU) and per-machine (HKLM) keys set to 0x1 - but note the asymmetry: HKLM is the gate (only an admin can set it), whereas HKCU lives in your own hive and is user-writable. So HKLM = 0x1 is the finding that matters: if it's enabled but HKCU isn't, you simply set HKCU yourself and proceed. HKLM = 0x0 can't be fixed from a standard user, so setting HKCU alone does nothing. Check both:

CVE-2019-1388 (UAC certificate dialog)

A GUI-only escalation in the UAC consent flow. An old Microsoft-signed binary (hhupd.exe) carries a certificate whose Issued By field renders as a hyperlink (OID 1.3.6.1.4.1.311.2.1.10 / SpcSpAgencyInfo). Running it elevated and clicking that link opens a browser as SYSTEM; from there, View page source → Save As gives a SYSTEM file dialog, which doubles as a file browser - navigate to System32, show all files, and right-click → Open cmd.exe to get a SYSTEM shell (the dialog's own process is SYSTEM, so the child it launches is too).

Key constraints: it needs interactive GUI access (console or RDP), not just a shell, and it was patched in November 2019 - so it only lands on an unpatched host where you have a desktop. Always worth a try when you land in a GUI session as a low-priv user on an older build.

Scheduled tasks

Enumerate with schtasks /query /fo LIST /v or Get-ScheduledTask. Note the ceiling: a standard user cannot read admin-created tasks - their definitions live in C:\Windows\System32\Tasks, which users can't read - so your view is mostly your own tasks plus the built-in ones:

The real win isn't editing the task object - it's a script the task runs sitting somewhere with weak ACLs. A writable directory is the lead, but confirm the script file itself is writable before relying on it - a file can carry a protected, non-inheriting ACL that denies writes even when its parent folder grants Users RW:

Once the file is confirmed writable, append a beacon/one-liner to it and wait for the schedule. This is the scheduled-task instance of the general "a privileged process runs a file I can modify" pattern - the same shape as modifiable autoruns and service binaries. It's patient (waits on the schedule) but reliable.

Mounting captured virtual disks (VHDX / VMDK)

Hunting shares (Snaffler, covered in credential hunting) sometimes turns up .vhd / .vhdx (Hyper-V) or .vmdk (VMware) virtual disks - backups of live hosts. A disk image of a machine you couldn't escalate on is often more valuable than the live host: mount it offline and you have its entire filesystem with no ACLs in your way.

On Windows, right-click → Mount (VHD/VHDX) or Map Virtual Disk (VMDK), or Mount-VHD. Once mounted, the point is the offline registry hives - grab SAM, SECURITY, and SYSTEM from \Windows\System32\config\ and extract local hashes:

That local Administrator hash frequently works via pass-the-hash on other hosts in the environment (shared local-admin passwords). The hive-to-hashes mechanics are the same as Backup Operators; mounting a captured disk is just another way to reach an offline SAM without touching the live target - and it gives you everything HiveNightmare would, with no exploit (see kernel exploits).

Defense

  • AlwaysInstallElevated - never enable it; it's a direct any-user-to-SYSTEM path. Audit both Installer policy keys.
  • CVE-2019-1388 - patch (fixed Nov 2019); restrict interactive logon for low-privileged users on sensitive hosts.
  • Scheduled tasks - store task scripts in admin-only directories; audit ACLs on any script a privileged task runs, and baseline the scripts themselves.
  • Description fields - never store secrets in user/computer descriptions or comments; they're world-readable.
  • Virtual disks - treat .vhdx/.vmdk backups as crown-jewel data: encrypt them, lock the shares that hold them, and rotate local-admin passwords (LAPS) so a captured SAM hash isn't reusable across hosts.
  • LOLBAS - application control that allows all signed binaries won't stop these; alert on anomalous use (certutil fetching executables, rundll32 with odd arguments, msiexec installing from user paths).
