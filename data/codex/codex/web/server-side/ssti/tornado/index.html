Tornado (Python - Tornado web framework)

SSTI exploitation in Tornado templates - the {% import %} statement that reaches os/subprocess directly, handler-object loot, and reverse shells.

MITRE T1190, T1059.006D3FEND D3-EAL, D3-PEIMPACT ServerSideEval, RCE, FileRead

TL;DR

Tornado's template language is a thin wrapper over Python - templates compile to Python functions and run with no sandbox. Unlike Jinja2, it exposes a real {% import %} statement, so you reach os/subprocess directly without any class-graph walk.

Success indicator: id output (uid/gid line) in the response, or os.system returning 0.

Where this engine lives

  • Tornado web framework - Python async web server. SSTI happens when attacker input becomes part of the template source that gets compiled - most directly tornado.template.Template(user_input).generate(...), or any code that concatenates user input into a template string before rendering. Note the distinction: a RequestHandler's render(name) / render_string(name) take a template filename, so controlling only that argument is template-file selection / path traversal, not SSTI - the input has to reach the template body for expressions to evaluate.
  • Standalone tornado.template - the template module is sometimes embedded outside the web framework (email builders, code generators) because it's dependency-light.
  • Legacy Python stacks - Tornado predates ASGI and lingers in older Python services and internal tooling.

Tornado is the engine the second SSTI exploitation example in the Server-side Attacks module walks through - the one where Jinja2/Twig-specific payloads all return 500 and the working payload turns out to be {% import os %}{{ os.system('whoami') }}.

Note

The decisive tell is the {% import %} statement. Jinja2 has an {% import %} tag, but it imports other templates, not Python modules - {% import os %} raises in Jinja2. In Tornado, {% import os %} is a literal Python import os. If {% import os %}{{ os.getcwd() }} returns a path, you have Tornado (or another engine that compiles directly to Python, like Mako - see the fingerprint note below).

Splitting Tornado from Mako

Mako is the other "compiles to raw Python" engine and also evaluates Python expressions. Tell them apart by delimiter:

  • Tornado - {{ expr }} for output, {% ... %} for statements.
  • Mako - ${ expr } for output, <% ... %> for statement blocks, % ... for line statements.

If {{7*7}} evaluated, you are not on Mako (Mako would leave {{7*7}} literal and needs ${7*7}). So within the {{...}}-Python family, the working {% import %} statement points at Tornado.

Step 2 - Loot before escalating

Tornado's RCE is trivial, but the handler object is worth grabbing first - it is low-noise and cookie_secret alone is often game over.

handler.settings['cookie_secret'] is the key Tornado uses to sign secure cookies (set_secure_cookie / get_secure_cookie). With it you forge any user's tornado_user-style cookie and bypass authentication without needing RCE - the same leverage {{config.SECRET_KEY}} gives you on Flask/Jinja2.

When the sink is a bare tornado.template.Template outside a request handler, handler is not defined - skip straight to Step 3.

Common failure modes

  • {{config}} / {{self}} throw but {{7*7}} works. You are Python-family but not Jinja2. Try {% import os %}{{ os.getcwd() }} - if it evaluates, it's Tornado.
  • os.system returns 0 and no output. Expected - system returns the exit code. Switch to os.popen('...').read() to capture stdout.
  • {% import os %} raises a syntax error about end. Your payload opened a block Tornado expects you to close - but a bare {% import os %} needs no {% end %}. The error usually means a different block (a stray {% if %}/{% for %}) is unterminated.
  • Output is empty but no error. The sink rendered the template but discarded the expression value. Assign and echo, or make the whole payload a single {{ ... }} expression ({{ __import__('os').popen('id').read() }}).
  • handler is undefined. The template is rendered by bare tornado.template, not a RequestHandler. Loot via handler is unavailable; go straight to {% import os %} RCE.

Notes

  • No sandbox. Tornado has no equivalent of Jinja2's SandboxedEnvironment - there is no "sandboxed Tornado" to escape. If you can evaluate {{ ... }}, you have Python. This makes Tornado SSTI simpler and higher-impact than Jinja2 SSTI, where the sandbox and the class-graph walk add steps.
  • {% import %} is the whole trick. The subclass-walk gymnastics the Jinja2 page documents are unnecessary here - Tornado hands you import directly. Reach for the walk only if import and __import__ are both filtered.
  • {% end %} closes every block (not {% endif %} / {% endfor %}). Both a fingerprint and a requirement when your payload uses control flow.

Caution

{% import os %}{{ os.system('id') }} executes on the application server in the application's user context - the same blast radius as any RCE. Confirm scope before going past the {{ handler.settings }} / cookie_secret loot stage.
